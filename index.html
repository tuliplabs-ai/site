The control layer for AI agents that act.

AI agents now take real actions. We build the layer that keeps those actions under control: an open-source runtime that checks each one before it runs, a platform where a team sets the rules once, and Clusiana — small models we train to help make those calls.

One thesis

Agents become infrastructure only when what they do is governed: every risky action checked before it runs, held for a person when it matters, written to a record no one can quietly edit. The open-source runtime is the foundation — the platform operates it for a team, the lab's models plug into it, and everything writes to the same record.

Clusiana · control models

Trained to keep agents careful

Frontier labs train models to be capable; we train small models to keep agents careful — one for each decision in an agent's loop. The first, a model that decides whether an action should run, is trained and tested; a grounding judge already ships in the runtime; run judgment and routing are next. By design, none of them holds authority — a Clusiana opinion can never override your rules.

The runtime · Apache-2.0

Tulip, the runtime

Drop the admission gate around an action your agent already takes.

A refund, a host isolation, an account disable — it runs only after it clears policy, holds for a human when it matters, and lands on a tamper-evident audit trail you can replay. Wraps agents from LangChain, LangGraph, CrewAI, OpenAI Agents, LlamaIndex, and Google ADK — in Python and TypeScript, no rewrite.

Documentation → Source 
# drop the gate around an action your agent already takes
from tulip.control import (
    Action, admit, ControlPolicy, AuditTrail, AdmissionError,
)

policy = ControlPolicy()    # prod → human
trail  = AuditTrail()

risky = Action(name="refund", asset="cust:4821",
               blast_radius=1, kind="payment",
               environment="production")

try:
    await admit(risky, lambda: refund("cust:4821"),
                policy=policy, trail=trail)
except AdmissionError as e:
    print(e.decision.outcome)
    # → "require_human" — the refund did NOT run

About

Tulip Labs builds the control layer for AI agents that act.

The research is not the marketing arm of the product — it is where the product's claims get attacked in public. A runtime that says "the model cannot talk its way past the gate" and "the record cannot be forged" makes falsifiable claims, and falsifiable claims need a lab the way a lock company needs lockpickers. We publish the methods, merge the fixes upstream, disclose in coordination, and hold our own work to the bar we ask of an agent: state the scope, show the evidence, ship something a defender can run.

If our work touches a system you operate — or you'd like to collaborate — get in touch.

How we work

01Open by default

The work that matters is the work others can build on. The runtime is Apache-2.0; the research is published in full, tools included.

02Measured claims

Numbers with methods behind them. Before we claim something works, a test has to prove it against the real system — and a claim we can't prove is removed, not softened.

03Defender-first

Every security finding ships with something a defender can run today. We study attacks to build the audit, not the exploit.

04Reproducible

Experiments are numbered, scripted, and rerunnable. If you can't reproduce it, we haven't finished.
